### SQL执行过程

TCP连接MySQL服务器，8.0以前走查询缓存，解析器进行词法分析提取关键字，进行语法分析构建语法树，预处理器检查表、列是否存在，将select*展开，优化器确定查询使用的索引，没有则全表扫描，执行器从存储引擎读取记录

### InnoDB和MyISAM

索引都是B+树，但MyISAM索引和数据是两个文件分开存储，主键索引和辅助索引的叶子节点存储都是数据地址，而InnoDB的主键索引的叶子节点存储的是数据，辅助索引的叶子节点存储的是主键值

InnoDB支持事务、行级锁、外键约束，MyISAM不支持

### InnoDB存储结构

表数据存储在.idb文件中，由段、区、页、行组成

以页为单位进行读写，页默认大小为16KB

以区为单位进行分配空间，区大小为1MB，让逻辑上相邻的页物理地址上也相邻，减少磁盘的随机IO

段分为索引段、数据段、回滚段等

索引段：B+树非叶子节点的区的集合

数据段：B+树叶子节点的区的集合

回滚段：回滚数据的区的集合

#### 行存储格式

变长字段长度列表（逆序非必需）+NULL值列表（逆序位图非必需）+记录头信息+真实数据

记录头信息：删除标记+下一条记录位置（记录头和真实数据之间的位置）+记录类型

真实数据：行ID（非必需）+事务ID+回滚指针+字段数据

除了大对象字段，一行不能超过65535字节（不计记录头信息和隐藏字段）

一个页放不下一行时会将多出来的数据放到溢出页，用20个字节记录溢出页地址

### 索引

#### B+树

树查询和插入删除都快，二叉树层数多，红黑树也是二叉树还需要维护平衡，B树每个节点都挂了数据导致节点能装的子节点少从而增加了层数，B+树只有叶子节点存储数据，并且叶子节点之间是双向链表连接可以轻松范围查询

#### 优化索引

前缀索引

联合索引-覆盖索引

自增主键索引，新增直接追加，插入会导致裂页移动数据

#### 索引失效

后缀模糊匹配、对索引使用函数、对索引进行计算、字符串索引用整数查询、联合索引不走最左匹配、or只有一个索引

MySQL比较字符串和整数会自动将字符串转换为整数

### InnoDB事务

增删改默认开启事务

#### ACID

**一致性**

事务前后满足完整性约束（实体、参照、用户定义），通过持久性+原子性+隔离性实现

**原子性**

事务中的操作要么不做要么全做，事务失败通过undo日志回滚数据

**持久性**

写操作先更新缓存，然后写redo日志到磁盘，日志是顺序写，数据是随机写，所以写日志到磁盘很快

redo日志也有16MB的缓冲区，后台线程每秒写一次到磁盘，缓冲区被写了一半也会触发写磁盘

**隔离性**

三个并行事务问题，四个隔离级别

#### 并发一致性问题

**脏读**

一个事务读到其他事务没有提交的修改数据

**不可重复读**

一个事务内两次读取的数据不一样

**幻读**

一个事务内两次查询的记录数量不一样

#### 隔离级别

**读未提交**

直接读取最新数据，事务没提交就能被看到修改

**读提交**

事务提交才能被看到修改

**可重复读**

默认隔离级别，一个事务内看到的数据是一样的

**串行化**

给记录加上读写锁

#### 多版本并发控制

通过生成数据快照read view实现，读提交是每条语句都生成一个read view，可重复读是一个事务用一个read view

read view可以知道哪些事务已经提交，读记录的时候比较事务ID，如果小于等于已提交的事务ID说明可见，否则根据回滚指针找到undo日志的历史记录

### InnoDB缓存

系统启动时会申请一块128MB连续的内存空间作为buffer pool，读取数据时，如果不在缓冲池里再从磁盘上加载进来，写数据标记为脏页由后台线程写回磁盘

脏页回写时机：脏页被回收、redo日志满了、空闲时、系统关闭时

缓冲页有控制块，空闲链表的节点是空闲页的控制块，flush链表的节点是脏页的控制块

根据空间局部性，加载页的时候会将附近的页也加载进来，批量查询时热点数据被淘汰，解决办法是将LRU链表分成young区和old区，新加载页优先放到old区，只有被访问过的并且停留时间超过1秒的才会插入young区

### 主从复制

主库log dump线程发送binlog日志，从库IO线程接收binlog日志写到relay log中继日志中，返回ACK，由SQL线程读取执行

异步复制：默认，主库提交事务不等待从库复制

同步复制：等待所有从库返回ACK再提交事务

半同步复制：等待一个从库返回ACK再提交事务

### 开发笔记

显示复制源的二进制日志位置

```sql
show binary log status;
```

配置从数据库的主数据库

```sql
change replication source to source_host='localhost',source_log_file='mysql-bin.000001',source_log_pos=158,source_port=3306,source_user='root',source_password='root';
```

查看从数据库状态

```sql
show replica status \G;
```

查看日志信息

```sql
show binary logs;
```

清空日志信息

```sql
reset binary logs and gtids;
```
